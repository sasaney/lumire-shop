# لومیر — فروشگاه محصولات آرایشی و بهداشتی

سایت فروشگاهی کامل با Next.js (بدون وردپرس)، شامل:
- فروشگاه (صفحه اصلی، دسته‌بندی، جستجو، صفحه محصول، سبد خرید، ثبت سفارش با پرداخت در محل یا کارت به کارت)
- **داشبورد خریدار**: `/dashboard` — مشاهده سفارش‌ها و اطلاعات حساب
- **داشبورد ادمین**: `/admin` — مدیریت محصولات (افزودن/ویرایش/حذف)، مدیریت سفارش‌ها (تغییر وضعیت)، لیست کاربران، آمار کلی
- **ورود بدون پیامک**: ایمیل + رمز عبور، یا کد تایید ۵ رقمی ارسالی به ایمیل (OTP ایمیلی)

## اجرا روی سیستم خودتان

```bash
npm install
npm run dev
```

سپس آدرس `http://localhost:3000` را باز کنید.

### حساب ادمین پیش‌فرض (داده نمونه)
- ایمیل: `admin@lumire.com`
- رمز عبور: `Admin@1234`

⚠️ حتماً بعد از اولین ورود، این رمز را از دیتابیس تغییر دهید یا کاربر ادمین جدیدی بسازید و این حساب نمونه را حذف کنید.

## دیتابیس

فعلاً داده‌ها در فایل `data/db.json` ذخیره می‌شوند (ساده و بدون نیاز به نصب دیتابیس، مناسب برای تست و راه‌اندازی اولیه).
برای فروشگاه واقعی با ترافیک بالا، توصیه می‌شود این لایه (`src/lib/db.ts`) با یک دیتابیس واقعی مثل **PostgreSQL** یا **MySQL** (با Prisma) جایگزین شود — ساختار کد طوری نوشته شده که این جایگزینی ساده باشد.
فایل `data/db.seed.json` یک نسخه نمونه/اولیه از دیتابیس است؛ هر وقت خواستید داده‌ها را ریست کنید کافیست محتوایش را در `data/db.json` کپی کنید.

## ارسال کد تایید ایمیلی (OTP)

اگر متغیرهای زیر را در فایل `.env.local` تنظیم نکنید، سایت در **حالت آزمایشی** کار می‌کند: کد تایید در پاسخ API و در ترمینال نمایش داده می‌شود (برای تست، بدون نیاز به ایمیل واقعی).

برای ارسال ایمیل واقعی، یک فایل `.env.local` بسازید:

```
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=your@email.com
SMTP_PASS=your-password
SMTP_FROM=your@email.com
JWT_SECRET=یک-رشته-تصادفی-و-طولانی-برای-امنیت
```

می‌توانید از سرویس‌هایی مثل **Zoho Mail**، **Mailgun**، یا حتی جیمیل (با App Password) به‌عنوان SMTP استفاده کنید.

## دیتابیس واقعی (Supabase) — لازم برای دیپلوی روی Vercel

فضای فایل روی Vercel فقط-خواندنی است، پس نسخه‌ی JSON فایلی برای پروداکشن آنجا کار نمی‌کند مگر به Supabase وصل شود:

1. یک پروژه در [supabase.com](https://supabase.com) بسازید (رایگان).
2. وارد **SQL Editor** پروژه شوید و کل محتوای فایل `supabase-schema.sql` (کنار همین README) را اجرا کنید — این یک جدول به اسم `app_state` می‌سازد.
3. از **Settings → API** مقدار `Project URL` و کلید `secret` (نه anon/publishable) را بردارید.
4. این دو مقدار را به‌عنوان `SUPABASE_URL` و `SUPABASE_SECRET_KEY` هم در فایل `.env.local` محلی و هم در تنظیمات Vercel وارد کنید.

اگر این دو متغیر ست نشوند، سایت خودکار به حالت فایل محلی (`data/db.json`) برمی‌گردد — مناسب تست سریع بدون دیتابیس، اما **نه برای Vercel**.

## دیپلوی روی گیت‌هاب و Vercel

1. یک ریپازیتوری جدید در گیت‌هاب بسازید و کل پوشه‌ی پروژه (بدون `node_modules` و `.next`) را push کنید.
2. وارد [vercel.com](https://vercel.com) شوید → **Add New Project** → ریپازیتوری را انتخاب کنید. Vercel به‌طور خودکار Next.js را تشخیص می‌دهد و نیازی به تنظیم دستی build command نیست.
3. قبل از اولین دیپلوی (یا در تنظیمات پروژه → Environment Variables)، این متغیرها را اضافه کنید:
   - `SUPABASE_URL`
   - `SUPABASE_SECRET_KEY`
   - `JWT_SECRET` (یک رشته‌ی تصادفی طولانی)
   - `SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_FROM` (اختیاری — بدونشان OTP در حالت آزمایشی کار می‌کند)
4. Deploy را بزنید.

⚠️ محدودیت شناخته‌شده: من از سندباکس خودم به `supabase.co` دسترسی شبکه ندارم، پس نتوانستم اتصال واقعی را از اینجا تست کنم — کد به‌درستی نوشته و build شده، ولی تأیید نهایی (آیا واقعاً رکورد در Supabase درست می‌شود) باید بعد از اولین دیپلوی روی Vercel یا اجرای `npm run dev` با این env varها روی سیستم خودتان بررسی شود.

## هاستینگ جایگزین (بدون Vercel)

اگر خواستید به‌جای Vercel از گزینه‌های دیگر استفاده کنید:

1. **لیارا (Liara)** — پلتفرم ایرانی، از Next.js پشتیبانی می‌کند، پرداخت ریالی.
2. **سرور مجازی (VPS)** — نصب Node.js + PM2 + Nginx.

در هر دو حالت هم اتصال به Supabase (یا هر Postgres دیگر) برای نگهداری دائمی داده لازم است، مگر روی یک سرور با دیسک دائمی (نه سرورلس) اجرا کنید که در آن صورت همان فایل JSON محلی هم کار می‌کند.

## ساختار پوشه‌ها

```
src/app/            صفحات (فروشگاه، دشبورد خریدار، پنل ادمین)
src/app/api/        بک‌اند (API های احراز هویت، محصولات، سفارش‌ها)
src/components/      کامپوننت‌های رابط کاربری
src/lib/             منطق مشترک (دیتابیس، احراز هویت، ایمیل، سبد خرید)
data/db.json         دیتابیس فعلی (JSON)
```
